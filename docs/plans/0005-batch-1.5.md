## How headshots work in this engine

This is a flat raycaster — the bullet is a **horizontal** hitscan along the aim ray, and
`src/shooting.js` already picks *which* zombie it strikes (ray-vs-circle, wall-occluded).
There is no pitch, **but the crosshair has a vertical position** (`cursorY`, canvas px),
and every zombie is drawn as a billboard occupying a vertical screen band
`[drawStartY, drawEndY]` with its **head across the top fraction** of that band
(see `drawZombies` in `index.html`: head ≈ top 4–24 % of the billboard).

So a **headshot = the crosshair's `cursorY` lands in the projected head band of the zombie
the bullet hit.** That splits cleanly into two decoupled pure modules — the seam between
them is a single boolean `headshot`:

- **`hitzones.js`** turns *(projection band + `cursorY`)* → `headshot` boolean. (Geometry.)
- **`shooting.js`** consumes the boolean → bonus damage + bonus score. (Rules.)

Neither imports the other. The integration layer computes the boolean from one and feeds
the other.

## Task 1 — `src/hitzones.js` + `test/hitzones.test.js`  → **Claude (Opus)**

Pure, dependency-free vertical hit-zone geometry. No DOM, no imports.

**Frozen contract (exact):**

```js
export const HEAD_TOP = 0.02;      // head band starts this fraction down the billboard
export const HEAD_BOTTOM = 0.30;   // ...and ends here (a touch below the drawn head, fair aim)

// True when the crosshair's y falls in the target's projected head band.
//   drawStartY, drawEndY : the sprite projection's clamped vertical band, in canvas px
//                          (from src/sprites.js projectSprite; drawEndY >= drawStartY)
//   cursorY              : crosshair y in canvas px
//   opts.top, opts.bottom: override the band fractions (default HEAD_TOP / HEAD_BOTTOM)
export function isHeadshot(drawStartY, drawEndY, cursorY, opts = {}) { ... }
```

**Behaviour:**
- `h = drawEndY - drawStartY`. If `h <= 0` → return `false` (nothing drawn / behind camera).
- `topY = drawStartY + h * (opts.top ?? HEAD_TOP)`, `botY = drawStartY + h * (opts.bottom ?? HEAD_BOTTOM)`.
- Return `cursorY >= topY && cursorY <= botY` (band is **inclusive** at both edges).

**Tests to cover:**
- `cursorY` inside the head band → `true`; in the torso (below `botY`) → `false`; above the
  head (`cursorY < topY`, e.g. aimed over the shoulder) → `false`.
- Both band edges are inclusive (`cursorY === topY` and `=== botY` → `true`).
- `h <= 0` (e.g. `drawStartY === drawEndY`, or end < start) → `false`.
- `opts` overrides shift the band as specified.
- A small far-away billboard (tiny `h`) still classifies correctly (no off-by-band errors).
- Pure: inputs are plain numbers; nothing is mutated.

## Integration (this session, after both modules land)

In `index.html`'s firing block, replace the post-hoc hp-diff target search with:

1. `const hit = shootRay(MAP, player.x, player.y, Math.cos(aimAngle), Math.sin(aimAngle), zombies);`
2. If `hit`: `const pr = projectSprite(player, FOV, W, H, hit.zombie);`
   `const headshot = pr.visible && isHeadshot(pr.drawStartY, pr.drawEndY, cursorY);`

4. Use `res.hitId` to place the blood / popup / corpse, and `res.headshot` to flavour the
   juice — a brighter/gold **"HEADSHOT"** popup, extra trauma, a sharper hit-marker.
